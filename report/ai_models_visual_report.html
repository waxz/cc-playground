01 Building block

Attention and the Transformer

To read “the animal didn’t cross the street because it was tired”, a model must connect “it” to “animal”. Older networks read one word at a time and carried a single memory that faded. Attention lets every word look at every other word directly and take a weighted average of what helps.

Try it: who does each word look at?

Weights below use hand-set illustrative scores (a real model learns them). Click a word.

The maths in four lines

q = x·WQ k = x·WK v = x·WV scoreij = qi·kj / √d weightij = softmaxj(scoreij) outi = Σj weightij · vj

Query: what I look for. Key: what I offer. Value: what I hand over. Dividing by √d keeps scores small so softmax does not collapse onto one word. The slider on the left mimics changing that scale.

02 Text

Language models: predict the next token

Cut text into tokens, then train one Transformer to guess the next token. Grammar, facts and reasoning patterns emerge because they all help the guess.

  1. PretrainNext-token prediction on trillions of tokens. Knowledge comes from here.
  2. Instruction tuneTrain on examples of requests and good answers.
  3. Preference tuneRLHF or DPO: learn which of two answers people prefer.
  4. Reason with RLReward correct answers on math and code; the model learns to think longer and check itself.
  5. Use toolsSearch, run code, operate software, loop on the results.

The maths

Pretraining loss L = − Σt log pθ( xt | x1 … xt−1 ) Scaling law (N params, D tokens) L(N, D) = E + A / Nα + B / Dβ RLHF objective max E[ r(x, y) ] − β · KL( πθ ‖ πref ) DPO loss (yw preferred over yl) −log σ( β [ log πθ(yw)/πref(yw) − log πθ(yl)/πref(yl) ] )

The KL term keeps the tuned model close to the original so it does not drift into odd text to please the reward.

Try it: temperature

Prompt: “The capital of France is …”. Logits are illustrative.

pi = exp( zi / T ) / Σj exp( zj / T )

Low T concentrates on the top choice. High T spreads probability to unlikely words.

SoftwareCode completion, review and agents that run tests and fix failures.

Limits. Models can state wrong facts fluently, and long reasoning chains can contain unchecked errors. Verifiable tasks (code, maths) improve fastest because the reward is trustworthy.
03 Continuous data

Diffusion: generate by removing noise

Take a real sample and add noise in small steps until only static remains. Then train a network to undo one small step. Start from static and apply it repeatedly, and you get a new sample.

Try it: add noise to a face

t = 0 is data, t = 1 is pure noise. Faint dots mark where each point began. Every point keeps the same noise direction, which is why it moves smoothly.

The maths

Forward (fixed) xt = √ᾱt · x0 + √(1−ᾱt) · ε ε ~ N(0, I) Learn to predict the noise L = E ‖ ε − εθ( xt, t, c ) ‖² Guidance (c = prompt) ε̂ = εθ(∅) + w · ( εθ(c) − εθ(∅) ) Flow matching (straight path) xt = (1−t)·x0 + t·ε L = E ‖ vθ( xt, t ) − ( ε − x0 ) ‖²

Guidance pushes the result toward the prompt by exaggerating the difference between “with prompt” and “without”. Flow matching learns a velocity along a straight line, so it needs fewer steps.

  1. Latent diffusionCompress with an autoencoder first, then denoise the small latent. Far cheaper.
  2. U-Net → DiTSwap the convolutional net for a Transformer over patches. Scales like an LLM.
  3. Flow matchingStraight paths, fewer steps. The default in many current systems.
  4. DistillationCompress 50 steps into 1–4.
  5. Video and actionsDenoise space-time patches, or chunks of robot motion.
Images and videoText-to-image, editing, video generation.
Robot controlDiffusion Policy and flow-matching action heads produce smooth motion chunks.

Limits. Sampling takes many network passes unless distilled, and diffusion on discrete text is still maturing against next-token models.
04 Seeing and reading

Vision-language models

Cut an image into patches and treat each patch as a token. After that, the image is just more tokens for a language model to read.

The maths

Patch tokens ti = Wpatch · flatten( patchi ) + posi Bridge to the LLM h = LLM( [ Wproj · ViT(image) ; embed(text) ] ) CLIP contrastive loss L = −(1/N) Σi log [ exp( sii / τ ) / Σj exp( sij / τ ) ] sij = cos( imagei, textj )

CLIP pulls matching image and caption together and pushes mismatches apart. That gives a visual encoder already aligned with language.

CLIP similarity grid (illustrative)

Rows are images, columns are captions. Training makes the diagonal bright and everything else dark.

Documents and screensRead invoices, charts, forms and user interfaces.
AccessibilityDescribe scenes and read signs aloud.
Computer-use agentsSee a screen, decide a click.
Robots (VLA)Same model, but the output is joint or gripper commands, often from a flow-matching head.
Limits. Fine spatial detail, counting and precise geometry are weaker than reading text. Robots also need grounding in real physics, which a still-image pretraining does not supply.
05 Prediction and planning

World models: imagine what happens next

A language model predicts the next word. A world model predicts the next situation, given the current one and an action. With it, an agent can rehearse in its head instead of on real hardware.

The maths

One-step dynamics st+1 ~ pθ( st+1 | st, at ) Dreamer-style latent state (RSSM) ht = f( ht−1, zt−1, at−1 ) memory zt ~ q( z | ht, ot ) posterior ẑt ~ p( ẑ | ht ) prior L = ‖ decode(h,z) − o ‖² + KL( q ‖ p ) JEPA (predict in representation space) L = ‖ predictor( sx, a ) − stopgrad( sy ) ‖² Training the policy maximise E[ Σk γk r̂t+k ] over imagined rollouts

Predicting in latent space ignores detail that does not affect decisions, such as leaf motion in the background.

Try it: why long rollouts go wrong

Error after k steps when each step adds ε and the model amplifies earlier error by λ.

ek = ε · ( λk − 1 ) / ( λ − 1 )

A measured example from this project

We tested whether physics plus a learned actuator model predicts a hopping robot better than a plain neural network that also sees the last few actions. The result went against the hypothesis.

One-second open-loop error (metres, lower is better) on out-of-distribution test logs; medians of 5 seeds. Source: poc_hybrid_wm/MEMO.md.

What it shows

Every learned model beat the nominal simulator (0.29 m). The constrained hybrid, however, was 2.1–2.6× worse than the plain history model at every data size, and its training loss stayed about 4× higher, which points to a mis-specified structure, not too little training.

Limits: the “real” plant was synthetic and low-dimensional, and the review was by one author. It is a result about this mechanism, not about real robots.

Where it is heading

  • Reasoning with RL on checkable tasks, spreading from maths and code to agents and robotics.
  • Cheaper attention: mixtures of experts, hybrid state-space stacks, very long context.
  • Flow matching as the common generator, including for actions and discrete data.
  • Unified multimodal models that read and write any medium.
  • World models as learned simulators for training and testing physical AI. The open problem is staying correct under real contact and long horizons.
