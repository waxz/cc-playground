# RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control
**Authors, venue, year:** Brohan, Brown, Carbajal, Chebotar, Chen, Choromanski, et al. (Google DeepMind); arXiv 2307.15818 (July 2023), CoRL 2023 · **Key:** `rt2_2023` · **OpenAlex citations:** 3628 · **Era:** vla
**Read status:** full text of the main body (Sections 1-6) and appendix Tables 4-6, failure cases and evaluation instructions; appendix model/training details (B-E) only located, not read.

## 1. Problem and motivation
Web-scale language and vision-language models have semantic reasoning that a generalist robot would need, but robot data is tiny by comparison, and prior uses of LLMs/VLMs in robotics mostly sat at the high level (planners that call separate low-level controllers that never benefit from web knowledge) (Sec. 1). The question the paper asks: can a large pretrained VLM be integrated directly into low-level control to improve generalisation and give emergent semantic reasoning?

## 2. Core idea in one paragraph
Write robot actions as text. Discretise each action dimension into 256 bins, map the bin numbers to tokens the VLM already has, and train the VLM to answer "What action should the robot take to [task]?" with a string such as "1 128 91 241 5 101 127". No new layers are added. Crucially, fine-tune on the robot trajectories and the original web vision-language data together (co-fine-tuning), so the model keeps its world knowledge while learning to act. At run time the output tokens are de-tokenised into end-effector commands, closing the control loop. Analogy: teach a well-read polyglot to speak one more "language", motor commands, without making it forget the others.

## 3. The mathematics
The paper has no numbered equations; its method is a representation plus a training recipe. The following are my formalisations of its description (simplified), not the paper's notation.

**Action tokenisation (Sec. 3.2).** The action is 6-DoF end-effector position and rotation displacement, gripper extension, and a discrete terminate flag. Every continuous dimension is discretised uniformly into 256 bins, giving 8 integers, written as the string "terminate $\Delta pos_x$ $\Delta pos_y$ $\Delta pos_z$ $\Delta rot_x$ $\Delta rot_y$ $\Delta rot_z$ gripper_extension". My simplified rendering: $b_k=\mathrm{round}\big(255\,\tfrac{a_k-a_k^{min}}{a_k^{max}-a_k^{min}}\big)$.

| Symbol | Meaning |
|---|---|
| $a_k$ | the $k$-th continuous action dimension |
| $a_k^{min},a_k^{max}$ | assumed range of that dimension (my notation) |
| $b_k\in\{0..255\}$ | bin index, emitted as a token |

Mapping to tokens: PaLI-X has unique tokens for integers up to 1000, so bins map directly; PaLM-E lacks this, so the 256 least frequently used tokens are overwritten to be action tokens (a form of symbol tuning).

**Training objective (my reading of Sec. 3.2).** Ordinary next-token cross-entropy on the answer string, over a mixture of robot examples and web VQA/captioning examples:
$$\min_\theta\; \mathbb{E}_{(x,y)\sim \mathcal{D}_{robot}\cup\mathcal{D}_{web}}\Big[-\sum_\ell \log p_\theta(y_\ell\mid y_{<\ell},x)\Big]$$
where $x$ is the image plus prompt, $y$ the target tokens (language or action tokens). The paper says the robot-to-web sampling ratio in each batch is balanced by "increasing the sampling weight on the robot dataset" (exact weights not stated in the main text).

**Constrained decoding.** For a robot-action prompt the model samples only from valid action tokens (Sec. 3.2), while for VQA prompts it may emit any text. This guarantees a decodable action.

**Chain-of-thought variant (Sec. 4.4).** Targets are augmented as "Instruction: ... Plan: pick rxbar chocolate. Action: 1 128 124 136 121 158 111 255." so the model writes a natural-language plan before the action tokens.

## 4. Method / architecture / algorithm
1. Start from a pretrained VLM: PaLI-X (5B and 55B) or PaLM-E (12B) (Sec. 3.1, 4).
2. Robot data: RT-1 data, 13 robots over 17 months in an office-kitchen environment, with language-annotated trajectories (Sec. 4); web data from the PaLI-X/PaLM-E mixtures (VQA, captioning, interleaved image-text).
3. Convert each robot step to a VQA-style example: image + "Q: what action should the robot take to [instruction]? A:" and target action string.
4. Co-fine-tune with hyperparameters inherited from the original PaLI-X and PaLM-E papers.
5. Deploy: the model runs in a multi-TPU cloud service queried over the network; the 55B model runs at 1-3 Hz, the 5B at about 5 Hz (Sec. 3.3). The 55B model is stated to be larger by over an order of magnitude than anything previously used for direct closed-loop control.
6. Baselines trained on the same robot data: RT-1 (35M parameters), VC-1, R3M (with an RT-1 backbone), MOO.

## 5. Achievements
- Appendix Table 4 (about 6,000 real trials overall): seen tasks are on par with RT-1 (RT-2-PaLI-X-55B 91, PaLM-E-12B 93, RT-1 92); on unseen-object/background/environment generalisation the unseen average is 62 for both RT-2 models vs 32 RT-1, 35 MOO, 10 VC-1, 12 R3M. The text summarises this as about 2x over RT-1 and MOO and about 6x over the others (Sec. 4.1).
- Emergent capabilities (Table 5): average 60 for RT-2-PaLI-X-55B and 40 for PaLM-E-12B vs 17 for RT-1 and 11 for VC-1, including symbol understanding (82 vs 16), reasoning (46 vs 16) and person recognition (53 vs 20). The text says the best model has more than 3x the average success of RT-1.
- Language-Table simulation (Table 1): RT-2-PaLI-3B 90 ± 10 vs LAVA 77 ± 4, RT-1 74 ± 13, BC-Zero 72 ± 3.
- Ablations (Table 6, unseen average): 5B from scratch 9, 5B fine-tune 42, 5B co-fine-tune 44, 55B fine-tune 52, 55B co-fine-tune 63; so pretraining, co-fine-tuning and scale all help.
- Chain-of-thought (Sec. 4.4, Fig. 7): fine-tuning a PaLM-E variant for a few hundred steps with a Plan step lets it handle commands like choosing a rock to hammer a nail; reported qualitatively only.

## 6. Limitations
**Stated by the authors (Sec. 5, App. G):** the robot gains no new physical skills from web data; motions stay within the robot-data distribution. Inference cost is high, real-time control is a bottleneck (1-3 Hz for 55B), and only a few VLMs can be used, with proprietary ones lacking fine-tuning APIs. Failure cases: grasping by specific parts such as a handle, novel motions like wiping or tool use, dexterous motions such as folding a towel, extended multi-indirection reasoning, and unseen object dynamics in Language-Table.
**Seen in hindsight (hindsight):** The models and data were not released, so the result was not reproducible outside Google, which motivated `openvla2024`. The 256-bin text tokenisation is coarse and slow for high-frequency, dexterous control, which `pi0_2024` addresses with continuous flow-matching action generation. The CoT evidence is qualitative. Evaluation used one embodiment and mostly pick-and-place semantics.

## 7. Place in the lineage
- **Builds on:** RT-1 (data, action discretisation), PaLI-X and PaLM-E (the VLM backbones), `flamingo2022` and `clip2021`-era VLMs, `vit2020`, `cot2022` (chain-of-thought), `transformer2017`.
- **Led to:** `openvla2024` (open-source 7B VLA with the same action-as-tokens idea), `pi0_2024` (VLA with a flow-matching action expert), and the broader VLA field (hindsight).
- **Single idea added:** treat actions as text tokens and co-fine-tune a web-pretrained VLM on robot and web data so one model both reasons and acts.
